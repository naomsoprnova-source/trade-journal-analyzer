# مخطط سجل الصفقات المنسق

اقبل CSV أو TSV بصف عناوين، أو JSON كمصفوفة كائنات. استخدم UTF-8؛ يدعم القارئ BOM. كل صف ملخص صفقة واحدة، لا تنفيذًا منفردًا. استخدم فاصلة عشرية نقطية دون فواصل آلاف، وأوقات ISO 8601 مع المنطقة الزمنية مثل `2026-01-01T10:00:00Z`. لا تنشئ بيانات مفقودة تلقائيًا.

| الحقل | التعريف |
|---|---|
| trade_id | معرف فريد نصي لكل صفقة عبر الملف؛ التكرار خطأ لا حذف تلقائي |
| status | closed أو open؛ تستبعد open من جميع نتائج الصفقات المغلقة |
| currency | عملة الربح والرسوم والتمويل نفسها؛ لا تجمع العملات المختلفة |
| closed_at | وقت الإغلاق؛ مطلوب للتراجع وليس لجمع صفقات مؤكد أنها closed |
| gross_pnl | الربح المحقق قبل الرسوم والتمويل، سالب للخسارة |
| fees | مجموع رسوم الدخول والخروج، عدد غير سالب؛ صفر صريح إذا انطبقت المجانية فعلًا |
| funding | صافي تمويل الصفقة: موجب للمقبوض وسالب للمدفوع؛ صفر صريح عند عدم الانطباق المؤكد |

يمكن بدل gross_pnl تقديم **جميع** `instrument_type=linear`, `side=long/short`, `quantity`, `entry_price`, `exit_price`, `contract_multiplier`. يجب أن تكون الكمية والأسعار ومعامل العقد موجبة وأن تؤدي الصيغة إلى عملة currency؛ لا يستنتج المحلل المعامل أو العملة. للعقود العكسية والخيارات أو أنواع غير معروفة اطلب gross_pnl المحقق وتعريفه بدل تطبيق صيغة خطية. عند تقديم gross_pnl تُستخدم قيمته ولا تُطبق اشتقاقات الأسعار.

الربح الإجمالي الخطي = (الخروج − الدخول) × الكمية × معامل العقد × (+1 للشراء أو −1 للبيع).

الصافي = الربح الإجمالي − الرسوم + التمويل. لا تخصم الرسوم مرتين من حقل صافٍ أصلًا. عامل الربح = مجموع الأرباح الصافية الموجبة ÷ القيمة المطلقة لمجموع الخسائر الصافية. عند أرباح بلا خسائر يُعاد `infinity_no_losses`؛ عند جميع النتائج صفرًا يعاد null (غير معرّف). نسبة الفوز = عدد النتائج الصافية > 0 ÷ جميع الصفقات المغلقة × 100.

التراجع المطلق = أقصى فرق من قمة سابقة لمنحنى الصافي التراكمي، بدءًا من صفر أو رصيد البداية المؤكد. التراجع النسبي = أكبر (القمة − القيمة الحالية) ÷ القمة، وهو غير متاح دون رصيد بداية موجب مؤكد. يمكن تجاوز 100% إذا صار منحنى الرصيد سالبًا؛ لا يُقص الرقم. لا يعكس هذا أدنى قيمة داخل الصفقة أو الأرصدة غير المحققة. تُجمع الأوقات المتساوية قبل قياسه.

الأرقام العشرية في JSON الناتج نصوص للحفاظ على الدقة؛ null يعني غير محسوب، وليس صفرًا. عند أي خطأ أساسي في مجموعة عملة تُحجب مجاميعها ومقاييسها بدل عرض نتائج ناقصة. عدم معرفة عملة أي صف يحجب النتائج الصافية لجميع المجموعات؛ صحّح البيانات أولًا. الملف الخالي يعطي حالة غير محسومة. السجل الذي يحوي صفقات مفتوحة فقط لا يعطي صافيًا مغلقًا مفترضًا.

احفظ أعداد JSON العشرية مباشرة كـ Decimal دون المرور بـ float. اقبل حتى 28 رقمًا معنويًا لكل مدخل، وأسًا عشريًا بين −28 و28، وقيمة مطلقة أقل من 1e29؛ ارفض ما يتجاوز ذلك صراحة بدل التقريب الصامت. تُجرى العمليات النقدية بسياق دقة داخلي موسع يناسب الحدود وعدد الصفوف. تُقرب النسب وعامل الربح عمدًا إلى 28 رقمًا معنويًا، ولا تغيّر هذه النسب المقربة تصنيف الصفقة أو مجاميع المال.

## مثال اصطناعي لا يمثل تداولًا حقيقيًا

```csv
trade_id,status,closed_at,currency,gross_pnl,fees,funding
synthetic-1,closed,2026-01-01T10:00:00Z,USDT,100,2,-3
synthetic-2,closed,2026-01-02T10:00:00Z,USDT,-40,2,1
synthetic-3,closed,2026-01-03T10:00:00Z,USDT,1,1,0
```

المتوقع: إجمالي 61، رسوم 5، تمويل −2، صافٍ 54؛ رابحة واحدة وخاسرة واحدة ومتعادلة واحدة؛ نسبة الفوز 33.333…%؛ عامل الربح 95÷41؛ تراجع مطلق 41، وبداية 1000 تجعل نسبته 41÷1095×100. هذه مطابقة حسابية للاختبار وليست إثبات ربحية.
